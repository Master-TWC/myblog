这次实验的要求很朴素：抓 [新华网](https://www.xinhuanet.com/) 的新闻列表页，取**标题、发布时间、作者、链接**，写进 `result.csv`，终端打印成功条数。

硬约束四条：必须伪装 User-Agent；相邻请求间隔 **≥ 2 秒**；超时自动重试 **3 次**；字段缺失写空字符串但**不能中断**。

![新华网首页：这次要爬的目标页面](/myblog/images/pachong/xinhuanet-home.jpg)

真正花时间的不是"把 HTML 抓回来"，而是后面三件事：**别猜选择器**、**限速别散落在业务代码里**、**动态站点怎么办**。下面按实际推进顺序记。

---

## 一、第一步就把"约束"钉进请求层

所有麻烦事都塞进 `Fetcher`：UA 伪装、限速、重试、编码判定、响应体上限。这样后面无论谁写解析，都不可能"忘记限速"。

限速按 `monotonic()` 算"上次请求**结束** → 这次**开始**"的间隔，重试也走同一把闸：

```python
def _throttle(self) -> None:
    """保证与上一次请求的间隔 >= min_interval（末尾追加 0~0.4s 抖动）。"""
    if self._last_end is None:
        return
    elapsed = time.monotonic() - self._last_end
    wait = self.min_interval - elapsed
    if wait > 0:
        time.sleep(wait + random.uniform(0, 0.4))
```

几个刻意的选择：

| 决定 | 理由 |
|---|---|
| UA 从 3 条桌面 UA 里**随机取一条，且全会话固定** | 中途换 UA 比不换更像机器人 |
| 只对**超时 / 连接错误 / 5xx / 429** 重试 | 404 重试三次纯属浪费，也更容易被记黑 |
| 抖动 0~0.4s | 固定 2.000s 的节奏本身就是特征 |
| `Retry-After` 最多听 30 秒 | 服务端让你等就等，别硬顶着上 |

编码是另一个坑。`requests` 在响应头缺 `charset` 时按 ISO-8859-1 猜，中文直接变乱码。所以判定链是固定的顺序：

1. 响应头 `charset`
2. 页内 `<meta charset>`
3. 严格 `utf-8`
4. `gb18030`
5. `charset_normalizer` 采样猜一次（只喂 64KB）
6. `utf-8` + `errors="replace"` 兜底

最后一步永远 `errors="replace"`——**宁可一个字符变问号，也不要整轮抓取崩掉**。

顺手加了单页 **8 MiB** 上限（流式读取，边读边算长度）：新闻页通常 150KB 左右，超过 8MiB 必是异常（gzip 炸弹或错误页面），直接失败且不重试。

限速和重试这两条硬约束，用一个离线自检脚本验：`selftest_fetcher.py` 实测相邻请求间隔 **2.03–2.25 秒**，模拟 Timeout 恰好尝试 **3 次**后抛 `FetchError`。

## 二、第二步：先勘察 DOM，再写选择器

这是整篇里最值钱的一条经验：**不要凭"新闻列表应该长这样"写选择器**。

先把页面存到 `.cache/`，再写两个探针脚本统计结构（`probe_structure.py` / `probe_dates.py`）。勘察结论直接决定了后面的架构：

- 首页和时政/国际/领导等频道，列表项是 `<li><span><a>标题</a></span></li>`——**整页没有任何时间字段**，日期只能从 URL 的 `/20261125/` 里抠；
- 只有地方频道 `news.cn/local/` 带日期，结构是 `div.item.item-style2` + `div.info > div.time`，而且 `.time` **只到"日"**；
- **列表页完全没有作者**——作者写在详情页正文末尾的 `（记者 汪子旭）`，`<meta name="author">` 基本指望不上。

第三条结论意味着：想要作者，就必须**二次请求详情页**。这是成本，但也是唯一的路。

于是架构变成"列表页拿骨架 + 详情页补血肉"：

```
列表页：标题 / 链接 / 日期（或从 URL 推）
详情页：精确到秒的时间 / 来源 / 记者署名
merge：谁更完整用谁
```

## 三、解析层：三种"看起来没问题"的写法全踩了

### 3.1 标题别用 `get_text(" ")`

第一版标题里出现了 `习近平总书记深情寄语航天 工作者`——中间多一个空格。

原因：`get_text(" ")` 会把**内联标签之间的分隔**也变成空格。标题里有 `<span>` 分段时就会多出空格。改成 `get_text()`（不加分隔符），只保留文本里真实存在的空格。

### 3.2 时间要"取更长者"，不是"后来的覆盖前面的"

列表页只给 `2026-11-25`，详情页给 `2026-11-25 10:14:52`。合并逻辑如果写成"详情页覆盖列表页"，某天详情页解析失败、退回只到日的值时，就会把已有的秒级时间**降级**掉。

所以 `merge()` 按字符串长度比较：

```python
if detail.published_at:
    # 精确到时分秒的详情页时间优先于列表页的"只到日"
    if not item.published_at or len(detail.published_at) > len(item.published_at):
        item.published_at = detail.published_at
```

### 3.3 署名有五种真实写法，还可能是"无空格多姓名"

抓 3 条试跑就翻车了。新华网的署名至少有这几种：

```
文字记者：郑良、陈弘毅、农冠斌      ← 通讯稿分角色
领衔记者：刘菁
（记者 汪子旭）                      ← 最常见的括号式
记者：徐凯鑫
编导/制作：胡碧霞 彭源               ← 视频稿
```

而且真实写法里还有 `（记者徐凯鑫、刘赫垚）`——**没有空格、多个姓名**。旧正则要求"单个姓名紧跟右括号"，直接匹配失败。

修法是按优先级排五个模式，并加 `BYLINE_HINTS`（"记者"/"编导"/"撰稿"）先做关键词预筛，避免正文里"记者从…了解到"这种句子被误认成署名：

```python
BYLINE_PATTERNS = (
    re.compile(rf"文字记者\s*[：:]\s*({NAMES})"),
    re.compile(rf"领衔记者\s*[：:]\s*({NAMES})"),
    re.compile(rf"[（(]\s*记者\s*({NAMES})\s*[)）]"),
    re.compile(rf"记者\s*[：:]\s*({NAMES})"),
    re.compile(rf"(?:编导|撰稿)\s*(?:[/／]\s*(?:制作|编辑|摄像))?\s*[：:]\s*({NAMES})"),
)
```

其中 `NAMES = r"[\u4e00-\u9fa5·]{2,8}(?:\s*[、,，和及]\s*[\u4e00-\u9fa5·]{2,8})*"`——允许姓名之间用顿号、逗号、"和/及"连接。

## 四、落盘：失败要降级，不要抛

抓取任务最忌讳"第 87 条详情页 404，整轮白跑"。所以规则是：

- 单条详情页失败 → 保留标题和链接，其余字段写空串，`Stats` 里计数；
- 单页列表失败 → 跳过这一页继续下一页；
- 每写一行 `flush()` → Ctrl-C 也能留下合法 CSV；
- 顶层兜底 → 只打印 `[致命错误] …`，不甩 traceback。

输出用 `utf-8-sig`（带 BOM）。这是给 Excel 看的——双击打开不乱码：

![result.csv 在 Excel 里双击打开，中文没有乱码](/myblog/images/pachong/csv-result.jpg)

这次实跑（`--limit 5`）的真实输出：

```
[列表页] https://www.xinhuanet.com/ -> 解析出 146 条
  [1] 习近平总书记深情寄语航天工作者
  [2] 把红树林"国宝"保护好
  [3] 爬楼就喘、夜里憋醒、脚踝肿？别急着怪"年纪大了"
  [4] 智利"沙漠开花"背后的气变之忧
  [5] 习近平对党内法规工作作出重要指示
成功抓取条数: 5
字段缺失(已填空字符串): 发布时间 0 条 / 作者 2 条 / 来源 0 条
```

注意 146 与 5 的差：列表页解析出 146 条候选（含专题、图集、重复），写入前按规范化 URL 去重，再按 `--limit` 截断。

全量跑（`--limit 0`）的账是：**写入 150 条，约 5.5 分钟**（2 秒限速决定的），**作者缺失 77/150 ≈ 49%**，详情页失败 1 条（列表页给了个被截断的 404 链接，已降级保留）。

49% 这个数字一开始以为是 bug，抽查后确认：电讯稿、图集、评论、视频、会见通稿的正文**确实没有署名**。

## 五、审查一轮，然后重构成五个类

先按"全部代码"过一遍，改掉这些：

| 问题 | 处理 |
|---|---|
| CSV/Excel 公式注入（标题以 `= + - @` 开头会被 Excel 当公式执行） | 写入前补单引号 |
| 终端 ANSI 控制序列注入（响应内容能篡改日志） | 正则剥掉 `\x00-\x1f` 等控制字符 |
| 响应体无大小上限 | 流式读取 + 8 MiB 硬上限 |
| `links.count()` 去重是 O(n²) | 改单遍 `Counter` |
| 解析时重复扫 DOM | 单遍 `_candidate_pairs()` 收集"锚点-块"对 |

然后重构成 `Fetcher` / `NewsParser` / `NewsCrawler` / `CsvWriter` / `CsvValidator` 五个类，同时保留原来的函数式入口——**CLI 参数和输出格式一行不改**。

怎么证明没改坏？重构前后各跑一次 `--limit 10`，比对 CSV 的 SHA256：

```
78FDB229…74EE7C0   ← 重构前后逐字节一致
```

这比"我看着没问题"可靠得多。

## 六、动态站点：三条路线，同一套管线

新华网是服务端渲染，`requests` 直接就能拿到 DOM。但如果目标是 Vue/React 站点，`requests` 只会拿到一具空骨架。所以扩了三条路线：

| 路线 | 做法 | 适用 |
|---|---|---|
| `static` | 原始 `requests` | 服务端渲染站点 |
| `api` | 直接请求列表背后的 JSON 接口 | 有清晰接口的 SPA（**首选**） |
| `render` | Chrome `--headless --dump-dom` 或 Playwright 渲染后交回原解析器 | 接口不可用 / 强反爬（兜底） |

关键设计：三条路线**只差两个注入点**——`fetcher.get_html()` 和 `parser.parse_list()`，抓取编排和 CSV 写入完全复用。用 `dynamic_crawler.py --strategy static|api|render` 切换。

怎么验证"动态渲染问题真实存在"？写了个本地基准站 `spa_demo.py`：骨架 HTML + `setTimeout` 之后用 JS 拼出列表，结构故意模仿新华网的 `div.item`，30 条数据，还带一个 `/api/news` 接口。

结果很干脆：**static 路线 0 条**（只有骨架），api 和 render 各 30 条。

三条路线的耗时实测（30 条，3 页）：

![三条路线的耗时对比](/myblog/images/pachong/route-bench.png)

| 路线 | 3 页耗时 | 单页均摊 | 拿到什么 |
|---|---|---|---|
| static | 4.73s / **0 条** | — | 只有骨架 |
| api（不限速） | **0.88s** | 0.29s | 时间到秒 + 作者 + 来源 |
| api（2s 间隔） | 5.47s | 1.82s | 同上（4s 是礼貌等待） |
| render（Chrome） | 2.43s | 0.81s | 列表 DOM：日期 + 标题 |
| render（Playwright 等选择器） | 3.92s | 1.31s | 同上 |
| render（Playwright 固定等 3s） | 10.44s | 3.48s | 同上（3s 是白等） |

两个结论：

1. **能逆向接口就逆向接口**。没有 2 秒礼貌约束时它比渲染快 3–4 倍，字段还更全（渲染拿到的只是列表 DOM）；
2. **等条件，不要等时间**。Playwright 从"固定等 3 秒"改成"等 `#list .item` 出现"，同样的结果从 10.44s 降到 3.92s。

有人会问：那还留着 render 干嘛？——它是**通用兜底**：接口被签名/加密挡住、或者页面必须真跑 JS 时，渲染路线不用改解析器就能上。

## 七、踩坑记录

| 现象 | 根因 | 处理 |
|---|---|---|
| `pip install` 在沙箱里必失败：`PermissionError … tmpXXXX\pip-*.whl` | 沙箱下 `mkdtemp()` 建的 0o700 目录内再写文件被拒 | `venv --without-pip` + 补丁脚本把 `mkdtemp` 换成 0o777 |
| Chrome 无头启动即崩：`platform_channel.cc:112 … 拒绝访问 (0x5)` | Chrome 的 Mojo IPC 依赖命名管道，受限环境禁用 | 换到放开权限的环境跑 |
| Playwright：`EPERM … mkdtemp 'playwright-artifacts-XXXXXX'` | 驱动临时目录不可写 | `--pw-tmp-dir` 把 TEMP 指到工作区 |
| 5 条新闻没有日期 | 链接指向 `/zt/` 专题聚合页，不是文章页 | `is_article_url()` 过滤 `/zt/` 和 `index.html` |
| 作者列出现 `9921` 这种数字 | 这条稿件的 `<meta name="author">` 里是内部稿件 ID | 见下 |

最后一条值得单独说，因为它是**我目前最不满意的地方**：

代码里作者是"先取 `meta[name=author]`，取不到再解析正文署名"。绝大多数稿件的 meta 是空的，看起来没问题；但个别稿件的 meta 里塞的是数字 ID——于是 `智利"沙漠开花"背后的气变之忧` 这一行的作者变成了 `9921`，而它的正文其实写着 `文/本报驻圣地亚哥记者 朱雨博 周佳谊`。

正确的顺序应该反过来：**正文署名优先，meta 只当兜底，并且要校验"像不像人名"**。这条还没有改——留在这里当作业。

## 八、已知限制与合规

- 作者覆盖率约 49%，这是稿件本身的问题，不是解析漏抓；
- `编导/制作：胡碧霞 彭源` 这种空格分隔的多作者只取到第一人；
- 未实现：`--append` 增量追加、`--allow-host` 白名单、`ETag/If-Modified-Since` 条件请求；
- 新华网列表页**不带分页**，想多抓只能靠多个频道页凑量。

最后是合规：这只是课程实验，仅供学习研究。请求间隔保持 2 秒以上、不并发、不抓需要登录的内容、遵守 `robots.txt` 与站点条款；新闻内容转载需获得授权。

代码结构和运行方式都写在项目 README 里，`crawler.py --limit 10` 一条命令就能复现上面的输出。
